Phase 1 · Problem design & planning

From a pile of parcels to a route

A depot has more parcels than one van can carry. The planner decides which parcels matter most, which ones fit, and the order in which to visit customers.

Pipeline

Each stage feeds the next and is timed separately

Prioritise

Merge sort
Order parcels by deadline, then priority, then value. Stable, O(n log n) in every case.

Pack

0/1 knapsack DP
Pick the parcel set with the highest value that fits the van's capacity. O(n·W).

Shortest paths

Dijkstra
From the depot and each stop, find real road distances and paths. O((V+E) log V).

Route

Nearest neighbour + 2-opt
Visit the closest unvisited stop next, return to depot, then uncross the tour. O(k²).

Algorithm selection

StageAlgorithmWhyTimeSpace
PrioritiseMerge sortGuaranteed n log n and stable; compared against insertion, quick and heap sortO(n log n)O(n)
Pack0/1 knapsack (DP)Parcels can't be split — greedy by ratio is not optimal, DP is exactO(n·W)O(n·W)
Shortest pathsDijkstra (binary heap)Road distances are non-negative; heap suits sparse graphsO((V+E) log V)O(V)
RouteNearest-neighbour TSPTSP is NP-hard; NN is a fast polynomial approximationO(k^2)O(k)
Improve2-opt local searchRemoves crossings in the NN tour — typically 10–20% shorterO(k^2) / passO(k)

n = parcels, W = capacity in kg, V / E = graph nodes / roads, k = stops on the trip.

Route-planning logic

  1. Collect the distinct destinations of the parcels chosen by the knapsack.
  2. Run Dijkstra from the depot and from every stop. This turns the sparse road map into a small complete graph over only the points we must visit.
  3. Build a tour with nearest neighbour: from the current point, drive to the closest unvisited stop; finally return to the depot.
  4. Apply 2-opt: reverse any segment whose reversal shortens the tour, until no such move remains.
  5. Expand each leg back into its real road path using Dijkstra's predecessor map, and add up the leg distances.
