06Observations & future optimisation

Sorting

Merge, quick and heap sort all follow n log n; insertion sort's n² curve is visible from a few hundred parcels. Quick sort is fastest in practice, but merge sort is kept because it is stable and has no O(n²) worst case. Python's built-in Timsort would be faster still (implemented in C).

Knapsack

Cost depends on capacity W, not just n. For heavy vans, weights can be scaled to coarser units (e.g. 0.5 kg) to shrink W, or the 1-D array used when only the value is needed. Greedy by ratio is a fast fallback but is not optimal.

Routing

Dijkstra is run once per stop; caching the distance matrix between runs, or using A* with straight-line distance as the heuristic, would cut this. 2-opt reliably shortens the NN tour by ~10–20%; Or-opt or Christofides could narrow the gap further.
